# Stage 9.2 — Box–Jenkins Identification

Stage 9.2 turns an input series into an auditable, deterministic candidate set. It does **not** estimate or select a model.

## Public API

```python
from stochx.timeseries import identify_box_jenkins

result = identify_box_jenkins(
    y,
    d=None,
    max_d=2,
    nlags=24,
    max_p=2,
    max_q=2,
    alpha=0.05,
)
```

The result type is `BoxJenkinsIdentificationResult`.

The existing `identify()` function remains unchanged for backward compatibility.

## 1. Input and missing observations

The input is a finite univariate sequence. NaNs are removed before identification using the existing StochX missing-value convention. Infinite values are rejected. At least two usable observations are required before and after differencing.

The result keeps both the original usable series and the transformed series so the transformation is auditable.

## 2. Differencing rule

`d` may be supplied explicitly.

When `d` is supplied, StochX applies exactly that many ordinary first differences and records the rule as `explicit differencing`.

When `d=None`, the smallest order `d <= max_d` is chosen for which the existing course-faithful sequential Dickey–Fuller procedure rejects the unit-root null at the configured `alpha`. The same Stage 7 critical-value, deterministic-specification, joint-F, Student-t, and common-lag conventions are therefore reused rather than duplicated.

The search is sequential:

```text
level (d=0)
   ↓ unit root not rejected
first difference (d=1)
   ↓ unit root not rejected
second difference (d=2)
```

The first stationary level is retained. If no level through `max_d` rejects, identification stops at `max_d` and records that the unit-root null was not rejected there; later stages remain responsible for deciding whether the candidate representation is adequate.

## 3. ACF/PACF computation

ACF and PACF are computed with the existing public StochX `acf()` and `pacf()` primitives. Stage 9.2 does not duplicate correlation formulas or redefine Stage 8 confidence bands, lag numbering, effective observation counts, or missing-observation treatment.

The returned `acf_result` and `pacf_result` therefore remain fully auditable through the frozen Stage 8-compatible numerical objects.

## 4. Order hints

The order hints use the **initial contiguous significant run** beginning at lag 1.

For ACF:

- significant lag 1 starts an MA hint;
- significance continues until the first non-significant lag;
- the resulting contiguous length is the MA order hint;
- later isolated significant spikes are recorded as evidence but do not increase the hint.

For PACF the same rule produces the AR order hint.

This prevents a single isolated high-lag spike from forcing an unnecessarily large model order.

All significant non-zero lags are retained separately in `acf_significant_lags` and `pacf_significant_lags` for auditability.

## 5. Deterministic candidate generation

Candidate orders are bounded by `max_p` and `max_q` and always use the identified `d`.

The candidate set contains:

1. the baseline `(0, d, 0)`;
2. pure AR orders `p=1..p_cap`;
3. pure MA orders `q=1..q_cap`;
4. every ARMA combination `p=1..p_cap`, `q=1..q_cap`.

The caps are the ACF/PACF order hints bounded by `max_p`/`max_q`. When a hint is zero but its maximum bound is positive, the cap falls back to one so the identification stage still offers low-order AR, MA, and ARMA alternatives.

Candidates are sorted lexicographically by `(p, d, q)` and returned as an immutable tuple. This ordering is part of the reproducibility contract.

No candidate is labelled selected. Selection belongs to later Stage 9 steps after estimation and residual validation.

## 6. Interpretation

The interpretation text must state:

- the selected differencing order;
- significant ACF/PACF lags;
- the initial contiguous ACF/PACF cutoffs;
- the resulting AR and MA hints;
- the number of generated candidates;
- that no model has been selected yet.

This is evidence-based identification, not an automatic claim that a particular ARMA model is correct.

## 7. Acceptance criteria

Stage 9.2 is accepted when:

- repeated calls with identical inputs/settings return identical `d`, hints, candidate order tuples, and interpretation;
- automatic differencing chooses the smallest stationary `d` under the frozen sequential DF procedure;
- explicit `d` is respected exactly;
- ACF/PACF come from the existing StochX numerical primitives;
- lag indexing and confidence bands remain inherited from Stage 8;
- AR/MA hints are based only on the initial contiguous significant runs;
- all candidate orders are within configured bounds and sorted deterministically;
- no candidate is marked selected;
- original and transformed arrays are protected from accidental mutation;
- invalid inputs fail explicitly;
- the legacy `identify()` API continues to work unchanged;
- Stage 8 source files and `CorrelogramResult` numerical/API behavior are not modified.

## 8. Non-goals

Stage 9.2 does not implement:

- AR/MA/ARMA/ARIMA estimation;
- residual validation;
- information-criterion selection;
- forecasting;
- seasonal automatic identification;
- new ACF/PACF or Ljung–Box formulas.
