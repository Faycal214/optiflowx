# Stage 9.6 — Box–Jenkins Forecasting

**Branch:** `stage-9-box-jenkins`

## Scope

Stage 9.6 forecasts only from the Stage 9.5 selected adequate candidate. It does not perform model selection, re-estimation, or residual validation.

## Public API

```python
from stochx.timeseries import forecast_box_jenkins

forecast = forecast_box_jenkins(
    selection,
    steps=12,
    alpha=0.05,
)
```

The result is `BoxJenkinsForecastResult`.

## Horizon and index

`steps` must be a positive integer. The returned index has exactly `steps` observations.

When the fitted model provides a datetime or period index, the next periods are inferred from its frequency. An explicit `forecast_index` may be supplied and must have exactly the requested horizon.

For non-date integer-like indices, the next integer positions are used. A generic fallback is `RangeIndex(1, steps + 1)`.

## Prediction intervals

The existing fitted-model forecast primitive supplies point forecasts and prediction limits. The Stage 9 result exposes:

- `forecast` / `point_forecast`;
- `standard_error`;
- `lower`;
- `upper`;
- `alpha` and `confidence_level`.

Finite interval bounds must satisfy `lower <= forecast <= upper`.

## Transformation restoration

The normal StochX ARIMA route estimates the differencing order inside the model, so its forecast is already on the original modeled scale. Stage 9.6 does not apply inverse differencing implicitly.

For callers that explicitly have forecasts on a differenced scale, set `forecast_on_differenced_scale=True` and provide `last_levels` plus `restoration_order`. The existing `restore_differences()` primitive is then reused for point and interval bounds.

Restoration metadata records:

- `scale`;
- `restoration_order`;
- `restored_from_differences`;
- `restoration_history_nobs`.

Seasonal inverse reconstruction remains outside Stage 9.6.

## Failure semantics

Forecasting fails explicitly when:

- no adequate model was selected;
- the selected candidate has no fitted model;
- `steps < 1`;
- `alpha` is outside `(0,1)`;
- an explicit forecast index has the wrong length;
- inverse differencing is requested without valid level history;
- required fitted-model forecast columns are unavailable.

## Result immutability

Core numerical forecast arrays are read-only. The table projection is a deterministic copy and does not change the frozen Stage 8 numerical contract.

## Acceptance criteria

- [ ] Forecasting accepts only a selected adequate candidate.
- [ ] Horizon validation is explicit and deterministic.
- [ ] Forecast and interval arrays have exactly the requested horizon.
- [ ] Future indices are aligned to the fitted series when possible.
- [ ] Explicit indices are validated against the horizon.
- [ ] Point forecasts and prediction intervals are exposed in one auditable result.
- [ ] Inverse differencing is explicit rather than implicit.
- [ ] Forecast metadata records model order, criterion, alpha, horizon, scale, and restoration settings.
- [ ] Core numerical arrays are immutable.
- [ ] Stage 8 `CorrelogramResult` and all Stage 8 numerical/API conventions remain untouched.
