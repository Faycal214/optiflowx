# Stage 9.3 — Candidate Estimation

Stage 9.3 takes the deterministic `(p,d,q)` candidates produced by Stage 9.2 and estimates them using the existing StochX model estimators. It does not select a model and does not redefine any Stage 8 numerical contract.

## Public API

```python
from stochx.timeseries import estimate_box_jenkins_candidates

result = estimate_box_jenkins_candidates(
    y,
    candidate_orders=((0, 1, 0), (1, 1, 0), (0, 1, 1), (1, 1, 1)),
)
```

Candidates are attempted in the supplied order. Duplicate orders are rejected. A failed candidate is recorded and does not abort estimation of later candidates.

## Existing estimators are the numerical source of truth

The dispatcher reuses:

- `fit_ar()` for `d=0, q=0, p>0`;
- `fit_ma()` for `d=0, p=0, q>0`;
- `fit_ar()`/`fit_ma()`/`fit_arma()` through `estimate()` for the corresponding stationary candidates;
- `fit_arima()` for candidates with `d>0`;
- `fit_arima()` for `(0,0,0)` so the white-noise/intercept-only candidate is representable.

No second likelihood or optimization implementation is introduced.

## Per-candidate audit fields

A successful `EstimatedCandidate` records:

- order `(p,d,q)`;
- model family;
- estimation observation count;
- coefficient estimates (`params`);
- parameter names;
- standard errors (`standard_errors`);
- t-statistics (`tvalues`);
- p-values (`pvalues`);
- log likelihood;
- `SIGMASQ`/residual variance estimate;
- AIC;
- SC/BIC;
- HQ;
- AR roots;
- MA roots;
- convergence status;
- residual series;
- the underlying `TSResult` for downstream residual validation.

Required numerical arrays are copied and marked read-only in the public candidate snapshot.

## Failure semantics

A candidate that cannot be estimated becomes a structured failure with:

- `success=False`;
- `converged=False`;
- empty numerical arrays;
- `NaN` statistics;
- the original exception message in `error`.

Other candidates continue to be estimated. Stage 9.4 decides whether successful candidates are adequate from their residuals.

## Determinism

For fixed data, candidate order, installed numerical backend, and estimator configuration, candidate ordering and returned snapshots are deterministic. Stage 9.3 does not rank or select candidates.

## Acceptance criteria

Stage 9.3 is complete when:

1. every deterministic Stage 9.2 candidate can be passed to the existing estimator dispatcher;
2. coefficient, SE, t-statistic, p-value, likelihood, variance, IC, roots, convergence, and residual information are auditable;
3. one failed candidate does not stop the remaining candidates;
4. duplicate/invalid candidate orders fail explicitly;
5. result arrays are immutable snapshots;
6. `stage8` numerical and public contracts are untouched.
