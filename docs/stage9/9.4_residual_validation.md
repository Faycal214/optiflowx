# Stage 9.4 — Residual validation and adequacy filtering

Stage 9.4 validates every estimated Box–Jenkins candidate before model selection.
It composes the existing StochX residual diagnostics and the frozen Stage 8 residual
correlogram; it does not redefine any Stage 8 numerical convention.

## Mandatory serial-adequacy rule

For candidate order `(p,d,q)`, the validator computes the frozen residual correlogram
with `model_df = p + q`. Every requested lag whose adjusted DF is positive must have
a finite Ljung–Box `Prob.` value greater than or equal to `alpha`.

If any required lag rejects the no-autocorrelation null, the candidate is inadequate.
A candidate with inadequate residual serial correlation is never eligible for model
selection, regardless of its AIC, SC/BIC, or HQ value.

Non-positive adjusted DF values remain governed by Stage 8 and therefore have undefined
probabilities; they are not themselves treated as failed serial-correlation tests.

## Optional checks

The validator can additionally require:

- zero residual mean (`require_mean_zero=True`);
- normality using Jarque–Bera and Kolmogorov–Smirnov (`require_normality=True`);
- no ARCH effects (`require_arch_free=True`).

Optional checks may only make eligibility stricter; they never override a serial-
correlation failure.

## Result contract

`CandidateValidation` records:

- candidate `(p,d,q)` order;
- estimation success;
- serial adequacy;
- overall adequacy/eligibility;
- residual observation count;
- validation lag count;
- alpha;
- the frozen `CorrelogramResult` for residuals;
- optional diagnostic test results;
- required-lag p-values;
- failed-check names;
- an auditable rationale;
- validation error text when diagnostics cannot be completed.

`BoxJenkinsValidationResult` exposes `adequate`, `inadequate`,
`has_adequate_model`, and a deterministic audit `table()`.

## Failure semantics

A failed estimation candidate is not revalidated. Its validation result is explicitly
ineligible and records the original estimation error.

A successful estimation whose residual validation raises an exception is also explicitly
ineligible and records a `validation` failure.

The complete candidate set is preserved: one failed candidate never aborts validation
of the remaining candidates.

## Stage 8 preservation

Stage 9.4 consumes, but never modifies, the Stage 8 residual-correlogram contract:
`AC`, `PAC`, `Q-Stat`, `Prob.`, `DF`, `model_df`, confidence bands, missing-value
handling, aliases, table projection, and immutable arrays remain unchanged.

## Acceptance criteria

- every estimated candidate receives an auditable validation decision;
- failed estimation is preserved as an explicit failure;
- serial adequacy is mandatory;
- no adequate candidate is represented explicitly by `has_adequate_model=False`;
- optional diagnostics can only tighten eligibility;
- residual correlograms are genuine frozen `CorrelogramResult` objects;
- candidate order and validation output are deterministic;
- Stage 8 numerical/API behavior is untouched.
