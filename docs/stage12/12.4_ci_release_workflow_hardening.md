# Stage 12.4 — CI and Release Workflow Hardening

## Purpose

Stage 12.4 closes the gap between a buildable distribution and a publishable release.

A release tag must be allowed to publish only after the tagged commit has passed the same repository-wide quality gates used for normal development and after the tag is proven to point at a commit contained in `main`.

## Required release verification

The release workflow must verify, on Python 3.12 at minimum:

- the complete `pytest -q tests --disable-warnings` suite;
- API, documentation, example, and package-identity coverage;
- every executable `examples/*.py` script;
- a strict `mkdocs build --strict`;
- source distribution and wheel creation;
- `twine check dist/*`;
- installation of the generated wheel into a clean virtual environment;
- imports of `stochx`, `stochx.stochastic`, and `stochx.timeseries` from outside the source checkout;
- installed version consistency with the package metadata.

The normal CI workflow remains authoritative for the Python 3.10/3.11/3.12 matrix and the `examples-and-docs` gate.

## Tag safety

For a release tag `vX.Y.Z`:

1. the tag must point to a commit that is an ancestor of `origin/main`;
2. the tag version must equal `stochx.__version__`;
3. the verification job must succeed;
4. only then may the publish job run.

A failing verification job must prevent publication.

## Workflow-dispatch behavior

Manual workflow dispatch may be used to exercise the verification job, but it must not publish to PyPI unless the workflow is executing from a `vX.Y.Z` tag.

## Compatibility

Stage 8–11 numerical and public API contracts remain unchanged. This stage changes only CI/release plumbing.

## Acceptance criteria

- [ ] Existing Python 3.10/3.11/3.12 matrix remains intact.
- [ ] `examples-and-docs` remains intact.
- [ ] Release workflow runs the complete test suite.
- [ ] Release workflow builds strict documentation.
- [ ] Release workflow builds sdist and wheel.
- [ ] `twine check` passes before publication.
- [ ] Clean wheel installation is verified.
- [ ] Tag target is verified to be contained in `main`.
- [ ] Release tag version equals package version.
- [ ] PyPI publication depends on successful verification.
- [ ] Manual verification cannot publish accidentally.
- [ ] No Stage 8–11 API or numerical contract is changed.
