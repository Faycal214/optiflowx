# Stage 12.6 — Release Candidate

## Candidate decision

The first release candidate uses semantic version `0.3.0rc1`.

Rationale: Stages 8–11 add backwards-compatible public functionality on top of the existing `0.2.x` line, so the release candidate is a MINOR-version pre-release rather than a patch release or a `1.0.0` stability declaration.

## Candidate baseline

The candidate must be created from a clean `main` commit after Stage 12.5.

The candidate commit is immutable once CI validation begins. No source, documentation, workflow, or metadata changes may be added to that candidate commit after validation starts.

## Candidate artifacts

The candidate build must produce exactly one source distribution and one wheel for `0.3.0rc1`.

Required validation:

- `python -m build`
- `python -m twine check dist/*`
- clean-environment wheel installation
- `import stochx`
- `stochx.__version__ == "0.3.0rc1"`
- public `stochx.stochastic` and `stochx.timeseries` imports
- complete test suite
- Python 3.10, 3.11, and 3.12 CI
- `examples-and-docs`

## Artifact integrity

The release-candidate workflow records SHA-256 hashes for the candidate artifacts. The hash manifest is part of the CI artifacts and is generated from the exact files produced by that candidate commit.

## Compatibility gate

The candidate must preserve all frozen Stage 8, Stage 9, Stage 10, and Stage 11 numerical and public API contracts.

## Acceptance criteria

- [ ] Version is `0.3.0rc1` everywhere the candidate version is intentionally surfaced.
- [ ] Candidate is built from `main` after Stage 12.5.
- [ ] Candidate commit has no pending source changes before CI starts.
- [ ] sdist builds successfully.
- [ ] wheel builds successfully.
- [ ] `twine check` passes.
- [ ] clean wheel installation passes.
- [ ] installed package version is `0.3.0rc1`.
- [ ] full test suite passes.
- [ ] Python 3.10, 3.11, and 3.12 pass.
- [ ] examples-and-docs passes.
- [ ] artifact SHA-256 manifest is generated.
- [ ] candidate artifacts are retained as immutable CI artifacts.
- [ ] no Stage 8–11 API or numerical contract changes occur.

## Stable-release gate

`0.3.0rc1` is not the stable release. A subsequent Stage 12.7 decision must explicitly choose between:

- promoting the same API contract to `0.3.0`; or
- beginning a deliberate `1.0.0` stability review.
