# Stage 12.6 — Candidate Manifest

Candidate version: `0.3.0rc1`.

Candidate branch: `release/0.3.0-rc1`.

The authoritative candidate commit is the tip of `release/0.3.0-rc1` after all release-candidate changes have landed. It must be contained in `main` and must not change after validation begins.

## Artifacts

The release-candidate workflow produces exactly one source distribution, one wheel, and a `SHA256SUMS.txt` manifest for the exact candidate commit.

## Hash policy

SHA-256 values are generated from the exact CI-produced files. The CI artifact bundle is authoritative; locally rebuilt artifacts must not replace it.

## Validation

The candidate is valid only when all required Python and documentation jobs pass against the same candidate commit SHA.
