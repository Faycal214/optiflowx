# Stage 12.5 — Changelog and Migration Guide

## Purpose

Stage 12.5 makes the accumulated Stage 8–11 feature surface explicit and gives users a practical migration path from the existing `0.2.x` release line.

This document describes the release content that has been implemented on `main`. It does not itself change the package version or declare a stable `1.0.0` release.

## What accumulated after 0.2.x

### Time-series and Box–Jenkins

The post-0.2 development line adds a documented Box–Jenkins workflow covering:

- deterministic differencing and identification;
- ACF/PACF order hints;
- candidate generation;
- candidate estimation using the existing AR/MA/ARMA/ARIMA estimators;
- residual validation and adequacy filtering;
- deterministic AIC/SC/HQ model selection;
- forecasting, transformation restoration, prediction intervals, and forecast metadata;
- numerical fixtures and end-to-end regression coverage.

The original time-series APIs remain available.

### State-space and Kalman filtering

Stage 10 adds a public linear-Gaussian state-space core:

```python
from stochx.timeseries import LinearStateSpace, KalmanFilterResult
from stochx.timeseries import kalman_filter, local_level_filter
```

Stage 10 preserves deterministic filtering, explicit missing-observation accounting, immutable numerical results, and the existing Stage 8/9 contracts.

### State-space extensions

Stage 11 extends the state-space layer with:

```python
from stochx.timeseries import (
    KalmanSmootherResult,
    kalman_smoother,
    KalmanForecastResult,
    kalman_forecast,
    LocalLevelEstimateResult,
    estimate_local_level,
    KalmanInnovationDiagnosticsResult,
    kalman_innovation_diagnostics,
    StateSpaceAdequacyResult,
    state_space_adequacy,
    StateSpaceWorkflowResult,
    run_local_level_workflow,
)
```

The Stage 11 contract keeps the Stage 10 filter as the canonical forward pass and composes smoothing, diagnostics, adequacy, likelihood estimation, and forecasting around it.

## Migration from `0.2.x`

### Package imports

The canonical package identity remains:

```python
import stochx
from stochx import stochastic, timeseries
```

No migration to a new package name is required.

### Existing stochastic-process code

Existing stochastic-process imports continue to work. The Stage 8–11 work is additive and does not require callers to rewrite existing Markov-chain, Poisson-process, CTMC, birth-death, probability-space, filtration, or martingale code.

### Existing time-series code

Existing `stochx.timeseries` objects remain the compatibility boundary. New Box–Jenkins and state-space functionality can be adopted incrementally:

```python
from stochx.timeseries import identify_box_jenkins
```

or:

```python
from stochx.timeseries import local_level_filter
```

There is no requirement to replace an existing AR/MA/ARMA/ARIMA workflow with state-space models.

### Missing observations

State-space users should rely on the documented scalar-dimension accounting rather than removing missing rows manually. Partial missing rows update only with observed dimensions; fully missing rows remain in the time axis and perform prediction only.

### Versioning

The project version is still single-sourced from `stochx/__init__.py`. The release candidate version will be chosen later in Stage 12.6.

## Compatibility guarantees

The following are treated as frozen compatibility boundaries:

- Stage 8 correlogram and diagnostic contracts;
- Stage 9 Box–Jenkins numerical and public API contracts;
- Stage 10 `LinearStateSpace`, `KalmanFilterResult`, `kalman_filter`, and `local_level_filter`;
- Stage 11 smoothing, forecasting, estimation, diagnostics, adequacy, and workflow APIs.

A release change must not alter a frozen numerical result merely to make packaging or documentation checks pass.

## Upgrade checklist

1. Install the release package.
2. Run the existing test suite before changing application code.
3. Keep existing `stochx` imports unless adopting a new feature.
4. Read the Box–Jenkins documentation before relying on deterministic candidate-selection behavior.
5. Read the state-space documentation before relying on missing-observation counts or prediction-interval semantics.
6. Re-run project-specific numerical regression tests before production use.
