# Stage 12.8 — Final Release Freeze

## Decision

StochX `0.3.0` is the stable release following the validated `0.3.0rc1` candidate.

The frozen release boundary includes the public stochastic-process API and the completed Stage 8–11 time-series and state-space surfaces.

## Release gates

The final release requires all of the following:

- `main` contains the exact release commit.
- Python 3.10, Python 3.11, and Python 3.12 complete the full test suite successfully.
- The examples-and-documentation checks are green.
- Source and wheel distributions build successfully and pass `twine check`.
- A clean wheel installation imports `stochx`, `stochx.stochastic`, and `stochx.timeseries` successfully.
- The package metadata reports version `0.3.0`.
- The final tag is `v0.3.0` and resolves to the validated `main` commit.
- The release workflow validates the tag/version match and publishes only after the verification job succeeds.

## Freeze rule

After the final release commit is tagged, no functional changes are permitted on that commit. Subsequent fixes must be new commits and, when necessary, a new patch release.

## Compatibility

Stage 8, Stage 9, Stage 10, and Stage 11 public and numerical contracts remain frozen. The `stochx` top-level import boundary remains canonical.

## Post-release

After `0.3.0`, development moves to normal maintenance and feature work. A future `1.0.0` release requires a separate deliberate stability review rather than being implied by `0.3.0`.

## Final CI refresh

This document is also the release-freeze audit point for the final stable-release validation on the current `main` commit. The authoritative CI result must correspond to the commit containing the corrected stable-version regression contracts, not to an earlier pre-promotion commit.
