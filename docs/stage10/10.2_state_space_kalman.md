# Stage 10.2 — State-Space and Kalman-Filter Core

Stage 10.2 introduces a deterministic linear-Gaussian state-space core without changing Stage 8 correlogram behavior or Stage 9 Box–Jenkins APIs.

## Scope

The public core provides:

- `LinearStateSpace`: validated time-invariant state-space specification;
- `kalman_filter()`: deterministic Kalman filtering;
- `local_level_filter()`: scalar local-level convenience model;
- `KalmanFilterResult`: immutable, auditable filtering output.

The model is

\[
x_t = F x_{t-1} + w_t, \qquad y_t = H x_t + v_t,
\]

with Gaussian process covariance `Q` and observation covariance `R`.

## Public API

```python
from stochx.timeseries import LinearStateSpace, kalman_filter, local_level_filter

result = local_level_filter(
    observations,
    process_variance=0.1,
    observation_variance=0.5,
)
```

For general models:

```python
model = LinearStateSpace(
    transition=F,
    design=H,
    state_cov=Q,
    observation_cov=R,
    initial_state=x0,
    initial_cov=P0,
)
result = kalman_filter(y, model)
```

## Frozen numerical conventions

### Initialization

`initial_state` and `initial_cov` are part of the model specification and are never inferred silently by `kalman_filter()`.

`local_level_filter()` defaults to the first finite observation as the initial level and uses an explicitly documented diffuse-like variance (`1e6`) when process variance is positive.

### Missing observations

NaNs are handled per observation dimension.

- finite dimensions are still used in the measurement update;
- missing dimensions are excluded from the update;
- an all-missing row performs prediction only and contributes no log-likelihood increment;
- infinite observations are rejected.

`effective_nobs` counts observed scalar measurements, while `nobs` counts time rows.

### Covariance update

The filter uses the Joseph-form covariance update and symmetrizes covariance matrices after propagation/update to reduce numerical asymmetry.

### Log likelihood

For each observed measurement vector, the Gaussian innovation likelihood is accumulated using a Cholesky factorization with a minimal numerical jitter only when the innovation covariance is numerically singular.

## Failure semantics

The core raises `ValueError` for:

- non-square transition matrices;
- incompatible matrix dimensions;
- non-finite model matrices or intercepts;
- negative-definite covariance specifications;
- empty samples;
- infinite observations;
- malformed controls.

The Stage 10.2 core does not silently coerce invalid configurations into a different model.

Controls are intentionally not part of the first core implementation. Passing non-empty control matrices therefore raises an explicit error rather than being ignored.

## Auditable result

`KalmanFilterResult` exposes:

- `filtered_state`;
- `predicted_state`;
- `filtered_cov`;
- `predicted_cov`;
- `innovations`;
- `innovation_cov`;
- `loglik` / `log_likelihood`;
- `nobs`;
- `effective_nobs`;
- `missing_observations`;
- `observed_dimensions`.

All numerical arrays are copied and marked read-only.

## Compatibility requirements

Stage 10.2 does not modify:

- `CorrelogramResult` or any Stage 8 AC/PAC/Q-Stat/Prob./DF conventions;
- Stage 8 table, plotting, interpretation, or residual-correlogram behavior;
- Stage 9 identification, estimation, validation, selection, or forecasting APIs.

The Kalman core is an additive time-series capability.
