# Stage 10.6 — Final Stage Integration and Regression Validation

Stage 10.6 is the final integration gate before the Stage 10 freeze. It verifies that the Stage 10 state-space/Kalman feature is usable through the public package namespace while the completed Stage 8 correlogram contract and Stage 9 Box–Jenkins workflow remain intact.

## Scope

The gate covers four layers:

1. Stage 8 public numerical/table contract;
2. Stage 9 public Box–Jenkins identification/estimation/validation/selection/forecasting path;
3. Stage 10.2 state-space/Kalman public API and frozen numerical behavior;
4. Stage 10.5 user-facing documentation/example integration.

The integration tests are additive. They do not redefine any Stage 8, Stage 9, or Stage 10.2 numerical convention.

## Required invariants

- `CorrelogramResult` field names and numerical values remain unchanged.
- Stage 9 Box–Jenkins result types and public orchestration functions remain unchanged.
- `LinearStateSpace`, `kalman_filter`, `local_level_filter`, and `KalmanFilterResult` remain the Stage 10.2 public boundary.
- Stage 10 Kalman result arrays remain immutable.
- Deterministic Stage 10.3 fixtures remain reproducible.
- Stage 10.5 example code remains runnable.

## Regression layers

### Stage 8 compatibility

The integration test checks the representative correlogram workflow and frozen table projection columns:

`Lag`, `AC`, `PAC`, `Q-Stat`, `Prob.`, `DF`, `AC Lower`, `AC Upper`, `PAC Lower`, `PAC Upper`.

### Stage 9 compatibility

A deterministic sample is passed through the public Box–Jenkins identification path and the existing candidate estimation/validation/selection interfaces. The selected model must remain auditable and forecastable without requiring Stage 10 APIs.

### Stage 10 compatibility

A deterministic local-level Kalman workflow and a general `LinearStateSpace` workflow are executed through the public namespace. The integration test verifies the Stage 10.3 reference values, missing-observation accounting, and read-only result arrays.

### User-facing integration

The Stage 10 example is treated as a documentation-level executable contract. The example must import only public APIs and execute without an exception.

## Failure semantics

A failure in any layer is a Stage 10 integration blocker. The suite must fail rather than silently downgrade to a partial result.

No Stage 10.6 test may mutate existing Stage 8/9 numerical fields or weaken a frozen assertion simply to accommodate Stage 10.
