# Stage 10.5 — Documentation, Examples, and User-Facing Integration

Stage 10.5 makes the Stage 10.2 state-space and Kalman core discoverable and usable through normal StochX workflows without changing its frozen numerical or public API contract.

## Public entry points

```python
from stochx.timeseries import LinearStateSpace, KalmanFilterResult, kalman_filter, local_level_filter
```

Use `local_level_filter()` for the scalar local-level model and `LinearStateSpace` + `kalman_filter()` for general linear-Gaussian systems.

## User-facing example

The canonical runnable example is `examples/09_state_space_kalman.py`.

It demonstrates:

1. a deterministic local-level filter;
2. a general two-state model;
3. partial and fully missing observations;
4. auditable observation counts;
5. read-only result arrays.

## Integration boundary

Stage 10.5 is intentionally additive. It does not modify:

- `CorrelogramResult` or Stage 8 AC/PAC/Q-Stat/Prob./DF/confidence-band behavior;
- Stage 8 table formatting, interpretation, plotting, or residual diagnostics;
- Stage 9 Box–Jenkins identification, estimation, validation, selection, or forecasting APIs.

The existing `estimate()` and Box–Jenkins workflows remain unchanged. State-space filtering is exposed as a separate public capability.

## Documentation requirements

The user-facing documentation explains:

- what a state-space model represents;
- what `transition`, `design`, `state_cov`, and `observation_cov` mean;
- initialization rules;
- missing-observation behavior;
- `nobs`, `effective_nobs`, and `missing_observations`;
- deterministic behavior;
- immutable result arrays;
- explicit validation/failure behavior.
